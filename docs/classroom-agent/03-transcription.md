# 03 ASR、转写与纠错

[返回总览](README.md)

## 现状与问题

现有 DashScope/OSS 接入可复用。`transcription_service.py` 的 auto 模式失败会返回固定演示文本；`transcribe_and_store` 在 segments 为 None 时直接返回，存在未更新失败状态的路径；重跑直接追加转写片段。文字和时间戳没有纠错版本。

修改：`transcription_service.py`、`dashscope_asr_service.py`、`oss_service.py`、转写模型、课时 API；新增 `transcript_service.py`。

## 处理方案

1. 生产配置明确选择真实 provider；缺少配置在任务开始前失败。Mock 仅用于演示课程和自动化测试。
2. 将提交、供应商任务 ID、轮询、解析、保存分为可追踪阶段；网络超时先查询已有任务状态，避免无条件重复提交产生重复费用。
3. 每次处理固定 audio_asset_id，创建新的 transcript_version。分批保存分片到构建版本，校验后再切换当前有效版本。
4. 所有成功、失败、取消、超时出口更新 job 状态。外部暂时故障可重试，格式错误和配置错误需明确修复后再发起。
5. 全量结果按序检查：顺序、时间范围、片段为空、供应商返回的不完整状态。静音或无法识别与调用失败使用不同错误类型。
6. OSS 临时文件在供应商确认完成或明确终止后清理；中断任务的清理由后台兜底，不因进程退出永久遗留。

## 纠错与版本规则

- 原始识别结果保留，纠错创建派生版本，记录 parent_id、修改人、修改原因与修改内容。
- 允许修改文字与说话人；修改时间戳需验证范围，并允许试听定位。
- `start_ms/end_ms` 缺失的片段不能伪造可点击的精确回听位置，可降级显示所属段范围。
- 发布纠错版本后，将旧笔记和知识索引标记为待更新，创建派生产物重建任务；重建完成前前端说明版本不一致。
- ASR 置信度只有供应商提供时保存，人工纠错不能被解释为“已证明全部正确”。

## 目标接口

| 接口 | 行为 |
| --- | --- |
| POST /lectures/{id}/transcription-jobs | 显式发起或重试，返回 202 和 job_id |
| GET /lectures/{id}/transcript | 指定或默认有效版本，支持 cursor 分页 |
| POST /lectures/{id}/transcript-revisions | 提交基于指定版本的修改集 |
| POST /transcript-versions/{id}/publish | 乐观并发检查后发布并触发重建 |

并发纠错必须提交 base_version；版本已经变化时返回冲突，不能静默覆盖他人修改。

## 验收

- ASR 失败不会写入演示文本，也不会生成正式笔记。
- 供应商成功但应用重启后，可根据已保存 task_id 恢复结果获取。
- 相同任务被重复执行时，一个有效版本内不会出现重复 seq_index。
- 上传新音频时旧转写不被误认成新音频结果。
- 专业术语、多人发言、长录音和静音样本均有人工核对记录，分别记录文字问题与时间戳问题。
