# 会议 Agent 到课堂 Agent：架构与流程讨论基准

版本：v1.0  
日期：2026-11-01  
性质：目标技术方案与后续讨论基准，不是当前实现完成情况说明。

## 1. 范围约定

本方案只做一件事：将原会议 Agent 的业务语义、输入输出和相关服务对应改造成课堂 Agent，保留原有系统分层、LangGraph 编排方式、四条处理分支、Harness 和双路检索思路。

讨论时不受当前课堂代码实现限制，也不将已有课堂改造代码中的机制自动纳入本方案。本文所述为设计目标；功能是否实现、实现质量和验证结果需要单独核查。

本轮不扩展为完整学习管理平台，不引入练习自动生成、自动批改、掌握度评估、个性化复习调度、多 Agent 自由辩论、实时多人课堂或新任务调度基础设施。

前序讨论中出现的“练习与复习闭环”不属于本基准范围。复习建议仅指从本节课堂资料整理出的文字建议。

## 2. 项目定位

课堂 Agent 接收课堂录音及课件，完成课堂笔记、知识点、例题和重点难点整理，并基于课程资料提供带来源引用的问答。

主链路：

```text
课程 / 课时 → 录音上传与课件解析 → 带时间戳转写
  → Planner → Budget Check
  → 四类课堂 Agent 动态并行
  → Output Validator → Review → 业务落库与索引
  → 资料路 + 结构化知识路检索 → 融合 → LLM 回答与引用定位
```

## 3. 架构对应关系

| 原会议系统 | 课堂系统 | 改造边界 |
|---|---|---|
| 会议管理 | 课程 / 课时管理 | 课程组织多个课时；一次录音处理以课时为单位 |
| 音频上传与 ASR | 课堂录音上传与 ASR | 复用转写接入思路，保留说话人和时间戳 |
| 知识文档管理 | 课件与补充资料管理 | 复用文档解析、分块和索引能力 |
| SummaryService | ClassroomService | 负责准备输入、调用工作流、实际落库和索引交接 |
| MeetingAgentState | ClassroomAgentState | 更换领域字段及产物类型 |
| LangGraph 工作流 | 课堂 LangGraph 工作流 | 保留规划、分支、校验回灌、确认和完成节点 |
| Harness | 课堂 Agent Harness | 保留预算、超时、重试、熔断、校验与运行记录 |
| 纪要与知识文档检索 | 课堂资料检索 | 检索转写、课件与已发布笔记 |
| 决策库检索 | 结构化课堂知识检索 | 检索知识点、例题与关联信息 |
| AI 对话 | 课堂学习问答 | 复用查询改写、双路召回、融合与 SSE 输出 |
| AgentRun 监控 | 课堂处理运行监控 | 展示分支状态、错误、耗时和模型用量 |

建议沿用的技术体系：React + TypeScript 前端，FastAPI 服务层，LangGraph / LangChain 编排，PostgreSQL + pgvector 数据与向量存储，通义模型、ASR 和 Embedding 接入。本文不要求升级依赖版本。

后端采用业务服务分层，不要求拆成多个微服务。结构化知识库可以直接使用关系表与 pgvector，不要求引入图数据库。

## 4. 四类 Agent 的固定对应

| 原节点 | 课堂节点 | 主要职责 | 主要输出 |
|---|---|---|---|
| summary_agent | classroom_notes_agent | 整理课堂结构与内容概要 | 课堂摘要、章节大纲、分节笔记 |
| action_items_agent | example_extractor_agent | 整理课堂上实际讲解的例题与步骤 | 题目、条件、步骤、答案、知识点关联 |
| risks_agent | focus_difficulty_agent | 提取教师强调、理解难点和常见错误 | 重点、难点、易错点、复习建议 |
| decision_extractor | knowledge_extractor_agent | 定位并结构化抽取课堂知识 | 概念、定义、公式、适用条件、关联 |

对应关系表示复用分支位置和编排机制，不表示继续使用行动项、风险、决策的领域字段或数据库表。

课堂笔记负责叙述与组织；知识点负责独立的结构化知识条目；例题负责具体题目及推导；重点难点负责强调与理解提示，避免四个 Agent 重复生成完整笔记。

例题 Agent 只整理来源中存在的题目，不自动出新题。重点难点 Agent 不判断个人薄弱点，不推断考试必考内容。未出现例题、公式或难点时，允许返回空列表。

## 5. 全流程与编排规则

### 5.1 输入准备

1. 用户选择课程并创建课时，上传录音，可附带课件。
2. ASR 生成转写片段，保留片段 ID、说话人、起止时间与顺序。
3. 课件解析为可定位文本，保留文档 ID、版本及页码或段落位置。
4. 服务层为本次运行固定输入快照，创建运行记录后调用课堂图。

课件是可选输入。ASR 失败时应明确失败，不将演示转写作为真实课堂内容继续发布。

### 5.2 Planner

分析课时标题、转写特征与资料概况，输出课堂类型、启用分支、文本处理策略、预算估计和规划原因。

课堂类型建议为：理论讲授、习题讲解、实验演示、复习、未知。课堂笔记分支默认必跑；其他分支按内容选择。Planner 失败时走明确的默认计划：笔记必跑，其余分支允许执行并返回空结果。

Planner 做任务选择，不直接生成最终笔记或知识点，也不承担任意工具自主规划。

### 5.3 Budget Check

检查预计 Token 和费用，确认输入是否满足上下文限制。短文本直接处理；超长文本需要压缩或分块策略。

具体长文本算法作为后续细化项。最低要求是不得静默截断后半节课；压缩、分块或覆盖不足必须在运行记录中明确。源片段定位在上下文变换后仍应保留。

预算不足时停止或采用已声明的降级策略，不返回伪完整的课堂结果。

### 5.4 动态并行

```text
START → planner → budget_check
    ├─ classroom_notes_agent ─────┐
    ├─ example_extractor_agent ───┤
    ├─ focus_difficulty_agent ────┤
    └─ knowledge_extractor_agent ─┘
             → output_validator
                 ├─ 可修正：回到对应失败分支 → 再校验
                 ├─ 无法继续：记录失败 / 待确认结果
                 └─ 通过：review → persist 标记 → END
```

各分支只写自己的产物字段。校验节点等待本轮所有选中分支完成后再执行；回灌时仅重新运行需要修正的分支，保留其余有效产物。重试次数有限，耗尽后不得标为校验通过。

### 5.5 知识点两步抽取

保留原决策抽取的两步结构：

```text
KnowledgeDetector：扫描原文，定位候选知识片段并保存来源
    → KnowledgeExtractor：逐片段抽取概念 / 定义 / 公式 / 条件 / 关联
    → 同义去重与关系整理
```

缺少适用条件或推导时保留缺失状态，不自行补成教师已讲内容。模型评分只能作为待确认或排序信号，不能等同于知识正确率。

### 5.6 校验、确认与发布

Output Validator 检查字段结构、来源引用有效性、产物间冲突与输入覆盖情况。结构校验不等于学科正确性证明。

Review 保留为确认扩展点。默认允许校验通过的结果发布；存在重要冲突或无依据结论时进入待确认状态。用户可查看引用并修正后确认。完整人工审批界面与恢复机制作为后续实现议题，不视为本文已完成能力。

persist 图节点仅表示流程完成，实际事务写入、产物关系保存和索引触发由业务服务层负责。

## 6. 最小数据契约

以下是逻辑实体，不预先规定数据库迁移与物理表复用方式。

| 实体 | 最小内容 |
|---|---|
| Course | ID、名称、归属主体 |
| Lecture | ID、课程 ID、标题、上课时间、处理状态 |
| TranscriptSegment | 来源版本、片段 ID、文本、说话人、起止时间 |
| CourseMaterial | 课件 ID、课时或课程归属、版本、解析内容和位置 |
| ClassroomNote | 课时 ID、摘要、大纲、分节正文、来源引用 |
| KnowledgePoint | 名称、说明、定义或公式、适用条件、关联条目、来源引用 |
| ClassroomExample | 题目、条件、有序步骤、答案、关联知识点、来源引用 |
| FocusDifficulty | 类型、内容、依据、相关知识点、复习建议 |
| AgentRun | 输入引用、执行计划、节点状态、错误、耗时、Token 与成本 |

所有生成产物至少绑定课时和本次输入版本。统一 SourceRef 至少包含：来源类型、来源 ID、来源版本、片段或页段定位、原文摘录；音频来源附起止时间。一个产物可以关联多个来源。

无原文支持的模型补充必须显式标记，不伪造 SourceRef。跨产物关联由汇合或落库阶段解析为稳定 ID，不要求并行 Agent 预知其他分支生成的数据库 ID。

共享状态建议包含：lecture_id、course_id、input_refs、transcript、materials、plan、notes、examples、focus_difficulties、knowledge_points、errors、各分支重试计数、validation_status、review_status。运行 ID 和预算上下文可以沿用 ContextVar 传递。

## 7. 入库与双路检索

发布后形成两条检索路径：

| 路径 | 旧会议对应 | 课堂检索内容 |
|---|---|---|
| 资料路 | 纪要 / 知识文档路 | 完整转写、课件、已发布课堂笔记 |
| 结构化知识路 | 决策路 | 知识点、例题及关联内容 |

资料路可沿用向量与词法混合检索；结构化知识路使用向量检索及领域字段过滤。两路召回后采用 RRF 融合，去重、选择上下文，再交给 LLM。

“双路”在本文固定指资料路和结构化知识路；资料路内部的向量 / 词法属于另一层召回机制。

入库保留原始来源，不仅索引摘要。课程与课时范围过滤必须在召回时生效，不能先跨范围取数据再依赖模型过滤。知识关联用于组织与补充上下文，不意味着本轮增加图推理引擎。

## 8. 课堂问答流程

```text
提问 + 对话历史 + 课程 / 课时范围
  → 查询理解与改写
  → 并行召回资料路与结构化知识路
  → RRF 融合 → 去重 / 重排 → 选择上下文
  → LLM 基于证据生成回答
  → 返回引用与 SSE 正文
  → 用户打开课件 / 原文 / 音频时间点
```

证据不足时明确说明。允许补充通用解释时，区分课堂依据与模型补充。引用应由服务端检索结果提供稳定身份，不接受模型编造的来源 ID。

问答基于已发布资料，不因一次提问重新执行课堂四分支工作流。

## 9. Harness 与技术边界

沿用预算、超时、有限重试、熔断、结构化输出校验与 AgentRun 记录。节点重试和工作流校验回灌应共用明确的调用上限，避免嵌套重试失控。

这些是设计要求，不意味着旧实现已具备严格的并发预算预留、生产级断点恢复或人工审批。本文不要求追加持久任务队列、Outbox、分布式租约、独立 AI 网关等设施；是否引入需另开议题并更新基准。

## 10. 验收口径

1. 输入一节课的录音及可选课件，能够按计划生成四类产物或明确的空结果。
2. 每类产物遵循独立结构，业务含义不混用会议行动项、风险或决策字段。
3. 知识点抽取能够追踪“定位片段 → 结构化条目”的两步结果。
4. 有依据的生成内容可以定位到原文；音频引用能够定位回听。
5. 无效输出触发有限回灌；失败、待确认和已发布状态可区分。
6. 问答能够召回资料路和结构化知识路，并遵守课程 / 课时范围。
7. 运行记录能解释执行了哪些分支、失败原因及模型用量。

验收不预设准确率、性能提升或学习效果数字；这些需要单独测量。

## 11. 后续讨论约定

后续提到“课堂 Agent 改造方案”，默认指本文 v1.0，而不是当前代码快照或此前更宽泛的学习平台方案。

固定内容：四分支对应、主流程、两路检索定义及本轮范围边界。可继续细化：各节点 JSON Schema、提示词、长文本策略、接口、数据表、确认交互和改造顺序。

新增功能或替换上述固定内容时，先明确变更点并更新本文版本。实现进度、验证记录和代码偏差另行记录，不能直接把本文目标当成已实现能力。
