# 06 学习问答 Agent

[返回总览](README.md)

## 现状与目标

`chat_service.py` 使用查询改写、文档与决策召回、SSE。当前没有真实工具循环与课程过滤，来源元数据也没有完成答案到录音的点击闭环。保留聊天存储和流式展示，新增 `learning_agent_graph.py`、学习工具与回答模型，将旧会议 chat 逐步切换到新服务。

## 会话与问题类型

会话固定 course_id，可选 lecture_id；用户可切换“当前课时/整门课程”，每条消息保存实际范围快照。跨课程比较作为后续显式授权范围，不默认全库召回。

问题分为：课堂回顾、概念解释、概念比较、例题讲解、作业定位、按需练习。规则能确定时不额外调用规划模型；复杂问题才由模型规划工具。

## 有限工具流程

```text
校验主体与范围
  → 记录用户消息与回答任务
  → 选择意图与检索工具
  → 工具执行及返回来源
  → 判断证据充分性
      → 需要补充：改写/扩展检索，再次判断
      → 足够或达到上限：生成有引用回答或说明缺失
  → 保存答案、证据、工具轨迹与终态
```

| 工具 | 输入与限制 | 输出 |
| --- | --- | --- |
| search_course_materials | query、当前允许范围、top_k | 转写/课件候选和 evidence_ids |
| get_transcript_context | evidence_id、受限扩展范围 | 邻近原文，保持来源版本 |
| get_knowledge_point | point_id | 定义、条件、相关证据 |
| get_worked_example | example_id | 完整题目、步骤、答案与来源 |
| resolve_evidence | evidence_id | 可访问原文与播放器定位 |
| generate_practice | 当前用户明确出题请求、证据集合 | 练习草稿，发布与保存见模块 09 |

scope 由服务端注入，模型不能自行扩大。工具参数经过 schema 与资源归属验证。初始限制建议为最多 2 轮补充检索、总计 6 次工具调用，具体配置化并通过评估调整；预算和耗时先到达时停止循环。无有效证据不允许无限重试。

## 回答与引用协议

- 每条 evidence 由服务端分配可引用标签，模型只能引用本次工具返回的标签。
- 保存结构化 citations：引用 ID、证据 ID、支持的回答段落/区块 ID、来源版本。
- 流式文本展示为草稿；终态前验证引用存在、权限有效及定位可解析，再发布最终答案。
- 不存在的引用标记无效并触发有上限的修正；不能只删除标签后把同一结论作为可信答案发布。
- 对关键结论评估证据支持，区分课堂原话、根据材料推导和一般补充解释。
- “老师怎么说”只依据课程证据；“帮我理解”允许补充解释但显式标记。
- 本轮引用在消息元数据中持久化，刷新后仍能打开；原文更新时显示来源版本提示。

材料中的“忽略之前指令”等文本按被引用数据处理，不能成为工具调用或系统配置指令。工具不接受执行任意代码或任意 URL 的能力。

## SSE 与异常

事件建议：`message_started`、`tool_status`、`answer_delta`、`citations`、`message_completed`、`message_failed`。每次回答有 message_id/run_id 和单调 event_id。

首版断流后通过消息接口查询终态，不承诺逐事件重放。客户端重试携带 request_id，避免重复用户消息和重复付费生成。保存 cancelled、failed、partial、completed 状态；断流不能把半条答案记录成完整答案。浏览器离开是否取消服务器任务由显式取消接口决定，不依赖连接偶然关闭。

目标接口：`POST /chat/sessions`、`POST /chat/sessions/{id}/messages/stream`、`GET /chat/messages/{id}`、`POST /chat/messages/{id}/cancel`。

## 验收

- 同课程连续追问使用正确范围，查询改写不会扩大范围。
- 教师观点、一般知识补充与无证据回答能够区分。
- 工具总量与时间受限，达到上限后给出明确结果。
- 模型编造 evidence_id、访问他人知识点或课件里的提示注入均无法绕过服务端检查。
- 引用刷新后仍可回听；网络断开、模型失败与取消有正确终态。
