# 02 录音、上传与音频资产

[返回总览](README.md)

## 现状与问题

`api/meetings.py` 一次性读取文件，`meeting_service.save_audio` 直接用上传文件名拼接路径；播放器响应固定为 audio/mpeg。主要课堂入口尚无浏览器录音闭环。长文件上传、文件身份、实际格式、时长及重传缺少统一管理。

修改入口：`backend/app/api/meetings.py`、`backend/app/services/meeting_service.py`、`backend/app/services/oss_service.py`、`frontend/src/features/meetings/components/audio-uploader.tsx`。

## A. 上传闭环：M0/M1

1. 新建音频资产服务，以服务端生成的 ID 作为存储键；原始文件名只用于展示。
2. 分段读取上传流，在读入过程中累计大小并校验上限；不等整段读入内存后才拒绝。
3. 检查扩展名、实际媒体容器、编码与可解码性，提取真实时长，校验供应商支持范围。
4. 文件写入临时位置，校验通过后再确认为完整资产。中断上传不触发 ASR。
5. 文件摘要与资产版本共同参与去重；同一文件跨用户仅可做内部存储优化，不能暴露他人资产存在性。
6. `audio_asset_id` 和转写任务在数据库提交后衔接，采用模块 07 的 outbox 保证提交与投递一致性。
7. 媒体接口校验课程权限，返回正确 MIME，支持播放器所需的范围读取；正式存储使用受控访问，临时授权链接设置有效期。

首版可以直接流式上传完整文件；分片续传是后续增强，不把普通进度展示描述成断点续传。

## B. 浏览器录音：M3

新增 `features/recording/` 和 `use-recorder.ts`，实现麦克风授权、开始、暂停、继续、停止与试听。通过浏览器实际能力探测选择编码，服务端必要时转码，不硬编码所有浏览器都支持相同格式。

- 录音按序号产生小块，缓存在浏览器持久存储并逐块确认上传。
- 服务端记录 `(recording_session_id, chunk_seq)` 唯一键、摘要和确认状态。
- 完成接口检查全部块齐全，再组装或转码为 ASR 输入，不能把所有媒体分片简单拼接后假定一定可播放。
- 页面重新打开后展示未完成录音，允许恢复上传或删除本地草稿；权限撤销、设备断开、存储不足时保存已有块并明确提示。
- 首版仅保证已保存分片可恢复，不承诺浏览器关闭后继续采集，也不承诺后台持续录音。

## 目标接口

| 接口 | 行为 |
| --- | --- |
| POST /lectures/{id}/audio | 完整文件上传，返回 asset_id 和处理 job_id |
| GET /audio-assets/{id}/content | 授权播放、范围读取 |
| POST /lectures/{id}/recording-sessions | 创建录音会话 |
| PUT /recording-sessions/{id}/chunks/{seq} | 幂等保存分片，返回摘要和确认序号 |
| GET /recording-sessions/{id} | 已确认分片与缺失范围 |
| POST /recording-sessions/{id}/complete | 校验并封装完整资产，返回任务 ID |

## 生命周期与验收

- 超限、伪造音频、特殊路径文件名被明确拒绝，输出路径始终处于资产目录内。
- 大文件上传不随文件大小线性占满应用内存；服务端和入口代理上限一致。
- 同一分片重传不重复写入；缺块不能完成录音。
- 中断、转码失败不生成可用录音或课堂笔记。
- 播放与拖动到中间位置正常；删除课程后媒体立即不可访问，清理由后台完成并可重试。
- 录音测试覆盖实际目标浏览器的权限拒绝、暂停恢复与刷新恢复；发布前记录支持范围。
