# 04 课堂整理与结构化抽取

[返回总览](README.md)

## 现状与替换范围

现有 `meeting_graph_v2.py` 编排摘要、行动项、风险与决策。决策定位仅读取前 8000 字符；压缩节点没有完整分块汇总链路。摘要 key_points 不等于结构化课堂知识点。

保留编排、结构校验和运行观测思路；新增 `classroom_graph.py`、课堂 schema、分块服务与抽取节点。旧会议图保留兼容期，不在原节点中不断增加业务条件。

## 目标工作流

```text
固定转写版本与处理配置
  → 构建带片段 ID 的完整输入清单
  → 按 token 预算分块，保留相邻上下文
  → 每块提取教学主题和证据范围
  → 抽取知识点、例题、教师任务、易混概念
  → 去重与跨块衔接
  → 汇总章节笔记
  → 结构、证据和覆盖校验
  → 草稿/待确认/发布
  → 索引构建任务
```

M1 先做章节笔记与作业，M2 增加结构化知识点和完整例题。节点拆分按独立输出和重试需求决定，简单抽取可以合并调用，避免每块固定触发大量模型请求。

## 分块与完整性

- 按转写片段边界切块，使用配置的模型上下文预算，预留提示词和输出空间。
- 重叠部分用于消歧，输出时依据原始片段范围去重；不能按重复次数判断知识点重要性。
- 保存 chunk_manifest：输入片段清单、核心覆盖范围、上下文范围、执行状态、输出引用。
- 汇总完整性以核心范围覆盖为准，不能以“抽取条数多”代替覆盖检查。
- 某块失败时仅重试失败块；可展示部分草稿，但不得发布为完整课堂笔记。
- 长推导或例题跨块时，依据连续片段回取上下文并追加抽取，不把半个题目当完整例题。

## 输出模型

| 产物 | 字段与业务规则 |
| --- | --- |
| 章节笔记 | title、outline、sections、关键结论、evidence_ids、来源版本 |
| 知识点 | name、type、definition、conditions、formula、explanation、evidence_ids、review_status |
| 例题 | statement、given、steps、answer、assumptions、evidence_ids、completeness |
| 教师任务 | task、due_at、due_text、task_type、evidence_ids；日期无法确定时保留原话并留空 due_at |
| 易混概念 | concepts、distinction、teacher_emphasis、evidence_ids；不等同于个人错题或薄弱点 |

统一保留 `content_origin`：课堂明示、基于材料推导、模型补充。教师任务只接受原文明确布置的内容；模型生成的复习建议另行存储。

“相似知识点”只建立候选关联；“先修关系”和“同一概念”需要明确依据或用户确认，不能由向量相似度直接决定。跨课时概念归并保留本次讲授记录，不能覆盖老师在不同课时使用的限定条件。

## 证据验证与发布

1. Schema 检查类型、必填项、公式与步骤字段。
2. 服务端确认 evidence_id 属于当前允许来源，原文引用能匹配来源内容；LLM 不生成数据库 ID 或媒体时间。
3. 结构有效与事实支持分开记录；引用存在也不代表引用支持结论。
4. 对无来源结论、原文冲突、缺失条件和不完整例题标记待确认；低置信度不自动补造内容。
5. 修改草稿保留编辑来源，发布新版本后触发索引；旧版继续供历史引用读取。

## 接口与验收

目标接口：`POST /lectures/{id}/processing-jobs`、`GET /lectures/{id}/notes`、`GET /lectures/{id}/knowledge-points`、`GET /lectures/{id}/examples`、`PATCH /note-versions/{id}`、`POST /note-versions/{id}/publish`。

验收包括：课程末尾新增的知识点能被抽取；跨块例题不截断；重叠内容不重复入库；无作业的课堂输出空任务并给出成功状态；模型故障不能以空数组冒充“没有知识点”；每条关键结论可核对来源。
